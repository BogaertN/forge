# AI.Web Slice 36F — Scope, Attachment, and Reference Operator Constraints Runtime Specification

## Status

Production implementation specification for the additive Slice 36F runtime boundary.

## Purpose

Slice 36F constrains accepted Slice 36E candidate trails using exact operator-law rules for scope, attachment, authority preservation, and explicit-context reference candidates.

It does not reinterpret source, create new grammar bindings, apply core RSOC operators, select a trail, select an attachment, resolve a reference, create concept meaning, assign predicate roles, grant permission, authorize capabilities, register routes, call tools, read memory, search files, inspect repository history, search the web, perform actions, deliver output, or authorize release.

## Accepted ancestry

The runtime accepts only validated outputs from:

1. Slice 36B deterministic source-field projection.
2. Slice 36D resonant operator candidate binding.
3. Slice 36E candidate resonant phase-trail construction.
4. The inert Slice 36C grammar-operator registry used by those predecessors.

Every constrained trail preserves the exact predecessor trail identity and creates a separate immutable candidate-only view.

## Closed scope-rule registry

The default registry contains exactly 21 rule contracts covering:

- negation;
- prohibition;
- condition;
- hypothetical status;
- quotation;
- reported speech;
- interrogation;
- imperative surface form;
- proposal;
- completion claims;
- exception;
- exclusion;
- modality;
- temporal status;
- operational status;
- quantification;
- privacy;
- disclosure limitation;
- evidence strength;
- claim force;
- reference.

A rule may activate only from an already accepted Slice 36D operator candidate. Slice 36F performs no source-form recognition and installs no word-list parser.

Rules without an accepted predecessor binding path remain registered awaiting binding authority. They do not create occurrences.

## Exact attachment preservation

Every scope occurrence preserves:

- exact source-span identifiers;
- exact code-point and UTF-8 ranges;
- exact source fragments;
- every lawfully generated possible governed span;
- possible parent binding identifiers;
- possible child binding identifiers;
- attachment rule identity and version;
- singular, multiple, malformed, unsupported, or unresolved attachment status;
- all authority-conversion guards.

No attachment is selected.

Rightward-scope rules preserve every exact prefix that can be constructed from accepted candidate bindings and unbound structural signals before a terminal boundary. They do not infer syntax or choose the most natural target.

Quotation rules preserve only the exact interior between paired delimiter coordinates. An unmatched quotation creates a malformed attachment and no invented interior.

## Explicit active-context registry

Reference analysis may inspect only an immutable ActiveContextRegistry supplied directly by the caller.

The registry is:

- caller supplied;
- immutable;
- explicit only;
- closed for the current analysis;
- exact-match only;
- incapable of automatic memory, file, repository-history, web, similarity, nearest-object, or capability-influenced lookup.

Supported lawful statuses are:

- ONE_SOURCE_SUPPORTED_REFERENCE_CANDIDATE;
- MULTIPLE_REFERENCE_CANDIDATES;
- UNRESOLVED_REFERENCE;
- UNSUPPORTED_REFERENCE_FORM;
- MISSING_CONTEXT_REFERENCE;
- PROHIBITED_CONTEXT_DEPENDENCY.

Reference candidates are never selected or resolved.

## False-authority conversion guards

The runtime always preserves guards against:

- possibility becoming certainty;
- question becoming command;
- request becoming permission;
- proposal becoming implementation;
- drafted becoming accepted;
- tested becoming verified;
- verified claim becoming world truth;
- failed becoming successful;
- rolled back becoming active;
- quoted instruction becoming active instruction;
- private becoming releasable;
- partial evidence becoming universal proof;
- recognized capability becoming authorized capability.

## Authority boundary

Every result must keep all of the following false:

- selected trail;
- selected attachment;
- resolved reference;
- selected meaning;
- concept meaning;
- predicate role;
- permission;
- capability authorization;
- route;
- tool routing;
- memory read or write;
- filesystem read or write;
- repository-history search;
- network or web access;
- embedding or similarity search;
- language-model use;
- action;
- delivery;
- release.

Concept and sense authority remain reserved for Slice 37.

Predicate and participant-role authority remain reserved for Slice 38.
