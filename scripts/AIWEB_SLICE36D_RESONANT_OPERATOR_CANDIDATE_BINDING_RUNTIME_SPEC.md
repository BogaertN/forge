# AI.Web Slice 36D — Resonant Operator Candidate Binding Runtime Specification

## Status

Production boundary specification for the additive Slice 36D runtime.

## Purpose

Slice 36D applies a closed set of exact, deterministic proposal rules to a validated Slice 36B source-field projection. It may produce zero, one, or multiple candidate associations between exact source spans and inert Slice 36C symbolic grammar-operator definitions.

A candidate association is not an applied operator occurrence, selected meaning, permission, capability route, memory instruction, or action.

## Governing chain

`Slice 36A source custody → Slice 36B source-field projection → Slice 36C inert operator registry → Slice 36D candidate associations`

Slice 36D may not bypass, repair, normalize, replace, or reinterpret any predecessor record.

## Closed v1 proposal-rule set

The v1 ruleset contains exactly fifteen rules:

1. exact whole-unit `not` candidate for `grammar_negation`;
2. exact initial `Do/do/DO` plus exact whitespace plus `not/NOT` candidate for `grammar_prohibition`;
3. exact whole-unit unresolved-reference forms for `grammar_reference`;
4. terminal period candidate for `grammar_boundary`;
5. terminal period candidate for `fbsc_loop_seal`;
6. terminal exclamation candidate for `grammar_boundary`;
7. terminal exclamation candidate for `fbsc_loop_seal`;
8. terminal question mark candidate for `grammar_boundary`;
9. terminal question mark candidate for `grammar_uncertainty`;
10. exact paired quotation marks as possible direct quotation;
11. the same exact paired quotation marks as possible quoted name;
12. the same exact paired quotation marks as possible quoted title;
13. the same exact paired quotation marks as possible literal string;
14. an unmatched supported opening quotation mark as possible incomplete quotation;
15. an exact action-like surface signal retained without an operator mapping for later Document 5 predicate/action-root analysis.

The rules do not constitute a general grammar, lexicon, predicate registry, concept graph, or parser.

## Exact rule requirements

Every rule carries:

- stable rule identity;
- rule version;
- exact match kind;
- exact authorized forms, sequences, or quotation-pair definitions;
- source-position and source-edge requirements;
- output kind;
- candidate operator identity where authorized;
- observable condition codes;
- satisfied prerequisite codes;
- missing prerequisite codes;
- conflicting evidence codes;
- possible parent and child rule identities;
- source-authority references;
- explicit false values for all prohibited inference mechanisms.

## Candidate record requirements

Each candidate preserves:

- candidate-binding identity;
- binding-set identity;
- source-event identity and source hash ancestry;
- source-field projection identity;
- complete predecessor field ancestry;
- exact source-span identities;
- exact code-point and UTF-8 byte ranges;
- exact source fragments;
- candidate operator key, version, definition identity, family and glyph;
- advisory phase-affinity metadata copied from the registry without assigning a phase;
- registry and ruleset identity and version;
- proposal-rule identity and version;
- exact observable, satisfied, missing and conflicting conditions;
- neighboring and materially competing candidates;
- possible parent and child bindings;
- a nonnumeric deterministic confidence basis;
- support, unresolved, unsupported and malformed states;
- explicit no-authority fields.

## Multiple candidates

Materially distinct candidates remain visible. Rule order does not select a winner. Quotation-mark ambiguity is represented by four competing candidates over the same exact source spans. No candidate receives a statistical rank or probability.

## Action-like source boundary

Document 3 permits provisional recognition of exact action-like source signals. Document 5 retains action-root, predicate-frame, participant-role and capability-binding authority. Therefore Slice 36D records exact supported forms such as `install` as `UnboundStructuralSignal` records and does not invent a grammar operator for them.

## Unsupported source

A partially unsupported source field remains fully preserved by Slice 36B. Slice 36D may retain exact candidates over supported spans, but marks them held by partial source and prohibits structural progression. It never deletes or normalizes unsupported material.

## Prohibited mechanisms

The runtime contains no:

- normalization or case folding;
- conventional tokenization;
- phrase-frequency inference;
- statistical confidence or ranking;
- embeddings or vector similarity;
- nearest-neighbor search;
- LLM or learned parser;
- memory resemblance;
- web or filesystem lookup;
- hidden parser result;
- capability-influenced interpretation;
- automatic candidate winner;
- operator application;
- phase assignment;
- concept, predicate or meaning selection;
- permission, route, tool, memory, action or delivery authority.

## Lawful statuses

- `CANDIDATE_BINDINGS_SUPPORTED`
- `CANDIDATE_BINDINGS_PARTIALLY_UNSUPPORTED`
- `CANDIDATE_BINDINGS_NONE`
- `CANDIDATE_BINDINGS_MALFORMED_SOURCE`
- `CANDIDATE_BINDINGS_LIMIT_EXCEEDED`
- `CANDIDATE_BINDINGS_FAILED`

Zero candidates and unresolved plurality are lawful results.
