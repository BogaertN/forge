# AI.Web Slice 37E Class/Relation Selection and Deferred-Scope Decision

## Decision

Admit only the smallest class and relation-type set required to organize the exact four Slice 37C concepts and prove the Slice 37E authority boundaries. Scale is not authority.

## Closed semantic-class set

1. `type_or_category_concept`
2. `expression_representation_communication_concept`
3. `occurrence_event_or_change_concept`
4. `action_type_concept`
5. `state_or_condition_concept`
6. `unknown_unclassified_or_foundationally_unsupported_concept`

The first, second, third, fifth, and sixth classes are foundational Document 4 families. `action_type_concept` is the bounded specialized class required by Document 4 Section 26.

## Explicit memberships

1. `forge_controlled_concept_identity` → `type_or_category_concept`
2. `source_expression_form` → `expression_representation_communication_concept`
3. `concept_admission` → `occurrence_event_or_change_concept`
4. `concept_admission` → `action_type_concept`
5. `unknown_concept_condition` → `state_or_condition_concept`
6. `unknown_concept_condition` → `unknown_unclassified_or_foundationally_unsupported_concept`

Multiple membership exists only where explicitly recorded. Parent-class metadata never generates inherited membership. Membership does not create evidence, memory, permission, action, delivery, identity, runtime, economic, or relation-instance authority.

`concept_admission` is classified as an action type because its admitted definition identifies a human-governed semantic admission act. This does not classify it as permission, approval status, a predicate, a capability, or an executed action.

## Closed relation-family set

1. controlled semantic distinction;
2. bounded non-equivalence;
3. conceptual component;
4. conceptual composition;
5. state relevance;
6. representation relevance.

## Closed relation-type set

1. `materially_distinct_from` — symmetric;
2. `not_equivalent_within_scope` — symmetric;
3. `conceptual_component_of` — directed and asymmetric;
4. `conceptually_composed_of` — directed and asymmetric;
5. `state_relevant_to` — directed and asymmetric;
6. `representation_relevant_to` — directed and asymmetric.

Only the component/composition pair receives an inverse declaration. Document 4 Section 30.18 establishes the Conceptual Component Relation Family, and Section 30.19 separately establishes the inverse-facing Conceptual Composition Relation Family. The inverse is stored as a separate versioned declaration so stable relation-type identities do not depend upon circular hashes. The declaration creates no reciprocal relation facts.

## Domain and range policy

Every domain and range is an exact tuple of admitted Slice 37E class identities. Eligibility requires explicit membership of both admitted predecessor concepts. No label, parent class, namespace, lexical mapping, similarity, or external ontology can supply missing membership.

`state_relevant_to` requires a state/condition or unknown/unsupported class on the domain side. `representation_relevant_to` requires the expression/representation class on the domain side. The other four foundational types accept the closed class set on both sides for later type review only.

## Relation states

The registry preserves four distinct policies:

- unknown relation;
- unsupported relation;
- conflicted relation;
- prohibited relation expansion.

These states are not automatically repaired, ranked, normalized, or completed.

## Prohibited implications

Sixteen explicit refusals preserve:

- eight class-membership-to-authority prohibitions;
- relation type is not relation fact;
- relation instance is not truth;
- source relation is not source reliability;
- evidence relation is not evidence validity;
- verification relation is not verified status;
- status relation is not status application;
- architecture relation is not implementation;
- class or relation does not create automatic inheritance.

## Deferred scope

Slice 37E does not add:

- relation instances or graph edges;
- source, document, claim, evidence, verification, status, temporal, quantitative, dependency, compatibility, or constraint relation inventories beyond the minimal proof set;
- occurrence interpretation or sense selection;
- CandidateMeaning construction;
- Slice 36 structural integration;
- predicate or participant-role authority;
- truth, evidence, verification, permission, memory, action, identity, economic, runtime, rendering, or delivery authority;
- external ontology or lexical-resource loading;
- automatic inference, graph completion, transitive closure, parent-membership inheritance, LLMs, embeddings, vectors, RAG, learned parsers, or neural classifiers.

Structural-to-concept candidate proposal remains assigned to Slice 37F.
