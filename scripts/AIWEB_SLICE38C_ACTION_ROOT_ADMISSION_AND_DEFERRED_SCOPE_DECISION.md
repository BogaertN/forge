# AI.Web Slice 38C Action-Root Admission Decision

## Decision

Admit exactly five Forge-owned action-root identities and their one-to-one predicate identities:

- `inspect`
- `report`
- `request`
- `verify`
- `simulate`

## Evidence basis

The decision is grounded in the accepted Slice 38A schema, accepted Slice 38B lifecycle law, the July 17, 2026 live source-authority packet, the canonical production roadmap, and Document 5 Parts I–III.

Document 5 explicitly requires these distinctions:

- inspect does not modify;
- report does not prove;
- request does not authorize;
- verify does not establish verified status;
- simulate does not execute.

Together they exercise read-only, communicative, authority-request, evidence-sensitive, and hypothetical action meaning without requiring live roles, frames, capability references, or effects.

## Deferred candidates

The following roadmap examples are deliberately not admitted:

- `approve` — requires controlled approval senses and authority-source distinctions;
- `install` — requires runtime target, artifact, effect, and implementation authority;
- `send` — requires content, recipient, privacy, delivery, and release authority;
- `remember` — requires memory sense, target, write/read/delete, privacy, and persistence law;
- `rollback` — requires target state, restoration scope, authority, execution, receipt, and proof.

Deferral is not rejection. It prevents consequence-bearing roots from being admitted before Slices 38D–38F can define the dependencies needed to keep them safe.

## Permanent separation

Every admitted root remains separate from surface wording, concept identity, speech act, frame identity, participant assignment, effect boundary, tool name, route name, capability name, permission, invocation, execution, result proof, memory state, rendering, and delivery.
