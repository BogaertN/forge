# Slice 36C — FBSC Grammar / RSOC Core Operator Separation Decision

## Binding decision

FBSC symbolic grammar operators and the ten RSOC core operators are related
parts of the larger architecture, but they are not interchangeable registries.

The Slice 36B0 registry preserves the ten RSOC core operator contracts:

```text
⟁ ⧧ ⧒ ⧀ ⧙ ⧜ χ(t) R̂ Ĉ Ê
```

The Slice 36C registry preserves the eight canonical FBSC Volume II grammar
operators:

```text
⊕ ⇋ ⚯ ↧ † ✎ ↠ ⟲
```

Slice 36C does not invent a direct mapping between these sets.

## Grace boundary

The FBSC grammar glyph `†` is recorded as Grace Override with advisory phase
affinity `Φ6`.

It is not silently equated with the RSOC Christ Function `χ(t)`.

A later explicit crosswalk may define a lawful relationship, but only if it
specifies domain, range, conditions, lineage preservation, entropy effects,
commutation restrictions and failure behavior. Until then:

```text
† ≠ χ(t)
```

for runtime authority.

## Extension-family boundary

The seventeen language-core extension responsibilities have no invented glyph,
no invented phase affinity and no direct RSOC mapping.

Their presence in the registry means only that the architecture reserves a
controlled responsibility class for later exact proposal rules.

## Compatibility boundary

No operator pair is declared compatible, incompatible or commutative in Slice
36C. Those tables remain uninstalled rather than guessed.

## Result

The registry can be inspected and validated, but it cannot interpret source,
create a candidate, assign a phase or invoke either an FBSC grammar operator or
an RSOC core operator.
