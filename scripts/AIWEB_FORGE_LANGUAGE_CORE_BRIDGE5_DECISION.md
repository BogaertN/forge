# Forge Language Core Bridge 5 Decision

## Decision

Connect an explicitly nominated Bridge 4 `CandidateMeaning` and one exact linked Slice 38 predicate/frame candidate pair through the accepted deterministic runtime:

1. Slice 40C expectancy,
2. Slice 40D congruity,
3. Slice 40E connectedness,
4. Slice 40F recoverable purpose,
5. Slice 40G gate composition,
6. Slice 40H MSM gate-result custody, and
7. Slice 41C selection-eligibility evaluation.

Progression stops before Slice 41D selected-meaning construction.

## Exact nomination boundary

A candidate can preserve more than one predicate/frame path. Bridge 5 does not choose the first path. When plurality exists, the caller must provide both the exact predicate-candidate ID and exact role-layout-candidate ID returned by the candidate preview.

## Slice 40G compatibility correction

All four gate families evaluate the same exact `GateCandidateInputReference`. Slice 40G previously applied a generic duplicate-ID prohibition to `family_candidate_input_refs`, making the lawful same-candidate chain impossible. Bridge 5 preserves the ordered exact references and cross-record equality checks while allowing the same exact candidate reference to appear once for each family. Mixed candidate references remain invalid.

## Authority boundary

Bridge 5 does not:

- select or rank meaning;
- call Slice 41D or Slice 41E;
- create a tool route;
- invoke a tool;
- execute an action or simulation;
- write source or memory;
- grant permission;
- call an LLM in Forge; or
- treat EchoForge output as Forge authority.

EchoForge's LLM deliberation boundary remains preserved. EchoForge output must re-enter Forge through deterministic meaning, gate, permission, and execution boundaries.
