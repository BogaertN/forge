# Bridge 4 Runtime Specification

## Explicit candidate custody syntax

`forge-language-candidate <inspect|report|request> :: <source request>`

## Explicit selection-hold syntax

`forge-language-selection-hold <inspect|report|request> :: <exact-candidate-id> :: <source request>`

## Runtime chain

Input custody -> source projection -> resonant binding -> phase trails -> scope/reference constraints -> structural derivation -> Slice 37 concept candidates -> Slice 38 predicate/role candidates using explicit action-root authority -> Slice 39F CandidateMeaning construction -> Slice 39G MSM-v1 candidate custody.

An exact candidate nomination creates validated selected-meaning boundary hold records only. It does not run Slice 41C, 41D, or 41E.

## Hard boundaries

- No action-root inference from text.
- No candidate ranking or automatic selection.
- One candidate is not automatic selection.
- No truth, evidence, permission, route, tool, action, memory, rendering, or delivery authority.
- No source or memory writes.
- No LLM, embedding, vector, RAG, or similarity authority.
- Ordinary unsupported requests remain on Bridge 3 structural preview.
