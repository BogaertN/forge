# AI.Web Slice 36H — Bounded Bootstrap Integration Runtime Specification

## 1. Status and purpose

Slice 36H connects the accepted Slice 36A through Slice 36G structural operator path to the isolated language-core bootstrap. It creates no public runtime authority. The integration remains disabled by default and is entered only through an exact, explicit, versioned invocation record.

Raw text alone activates nothing. Raw text alone is not a valid invocation. Importing the package, constructing a state record, listing fixtures, or obtaining a fixture record performs no pipeline stage. Each stage requires an exact, versioned predecessor record. No approved-caller catalog is installed. The path is standard-library only and offline.

## 2. Exact permitted chain

The only integrated chain is:

1. exact static synthetic fixture invocation, or a later-authorized exact approved caller;
2. Slice 36A input custody;
3. Slice 36B source-field projection;
4. Slice 36C controlled symbolic grammar-operator registry;
5. Slice 36D operator candidate binding;
6. Slice 36E candidate phase-trail construction;
7. Slice 36F scope, attachment and explicit-context reference constraints;
8. Slice 36G bounded structural derivation or explicit lawful non-progress.

No approved caller catalog is installed by Slice 36H. An invocation claiming approved-caller status is held before source custody.

## 3. Disabled state

`build_bounded_structural_bootstrap_state()` returns a frozen state with `enabled=False`.

The default state requires all of the following:

- disabled by default;
- explicit invocation required;
- exact accepted fixture only;
- offline execution;
- standard-library-only runtime;
- deterministic, read-only and in-memory operation;
- exact source preservation;
- operator-trace and phase-trace preservation;
- bounded supported profile only;
- no LLM or learned-model authority;
- no public route, capability, tool, action, rendering or delivery authority.

The integration enters the pipeline only when the caller constructs a separate state with `explicit_offline_developer_enable=True` and supplies an exact invocation from the static fixture catalog.

## 4. Exact fixture boundary

Slice 36H installs four synthetic, internal, immutable fixtures:

- `Do not install it.` — eight candidate structural results with unresolved reference and operator conditions preserved;
- `hello` — zero structural candidates with `NO_SUPPORTED_DERIVATION`;
- `"Alpha"` — four conflicting quotation candidates;
- `"Alpha` — one incomplete and malformed structural candidate.

The invocation carries only the fixture identity. It does not carry arbitrary raw text. The runtime retrieves the exact source from the closed fixture catalog after validating the invocation identity.

The catalog contains no production input, personal information, external document, memory item, URL, system path, capability, tool or action authority.

## 5. Bootstrap boundary verification

Before Slice 36A runs, the integration validates the existing isolated bootstrap boundary and an explicit offline bootstrap-adapter state.

The boundary must remain:

- disabled;
- fixture only;
- offline;
- deterministic;
- registered but not loaded;
- disconnected from `main`, routes, APIs and UI;
- free of persistent side effects;
- free of runtime and dependency effects.

The integration does not call the Slice 31 boundary-inspection fixture and does not load registered components dynamically.

## 6. Exact predecessor law

Every stage creates an immutable `BootstrapStageReceipt`.

Each receipt records:

- stage ordinal and exact stage identity;
- exact predecessor record identity;
- actual predecessor schema version;
- required predecessor schema version;
- predecessor exact Python record type;
- supporting record identities;
- exact output identity, schema version and record type;
- output-validation result;
- source-event identity and SHA-256;
- source-ancestry preservation;
- candidate-only status where applicable;
- complete negative-authority evidence.

The exact predecessor chain is:

- invocation record to Slice 36A custody result;
- custody result to Slice 36B projection result;
- projection result to Slice 36C registry snapshot;
- registry snapshot, with the projection as supporting evidence, to Slice 36D binding result;
- binding result to Slice 36E phase-trail result;
- phase-trail result, with an explicit immutable empty context registry, to Slice 36F constraint result;
- constraint result, with all earlier result identities as supporting evidence, to Slice 36G structural result.

A failed predecessor or output stops the integration. No later stage is called and no skipped-stage receipt is fabricated.

## 7. Result contract

A completed result contains the exact seven predecessor records and seven stage receipts. The result preserves:

- input custody;
- reversible source field;
- grammar registry identity and version;
- operator-binding result;
- candidate phase trails;
- scope, attachment and reference candidates;
- structural candidates or explicit lawful non-progress;
- exact source event, source SHA-256 and reconstruction proof;
- all non-progress reasons;
- rollback metadata;
- final Slice 36 acceptance metadata.

The result does not select a structural candidate or meaning.

## 8. Lawful completion states

Slice 36H has two successful completion states:

- `COMPLETED_STRUCTURAL_CANDIDATES` when one or more candidate structural results are preserved;
- `COMPLETED_LAWFUL_NON_PROGRESS` when zero structural candidates and an explicit non-progress result are preserved.

Zero candidates is not a crash and is not guessed away.

## 9. Permanent authority boundaries

The integrated path preserves these distinctions:

- source event is not meaning;
- source span is not tokenized cognition;
- source field is not concept;
- source observation is not grammar operator;
- operator candidate is not an applied core RSOC operator;
- candidate grammar-state application is not selected meaning;
- phase trail is not semantic truth;
- structure is not meaning;
- scope operator is not final attachment;
- reference candidate is not resolved reference;
- structural candidate is not CandidateMeaning;
- CandidateMeaning is not selected meaning;
- imperative surface is not permission;
- action-bearing structure is not capability authority;
- capability term is not tool route;
- quoted instruction is not active instruction;
- operator completion is not world-state completion;
- unsupported is not guessed;
- unresolved is not failed;
- containment is not deletion;
- correction is not mutation.

## 10. Prohibited activation and dependencies

The runtime performs no:

- automatic raw-text activation;
- hidden fallback parsing;
- conventional NLP semantic authority;
- external linguistic-resource loading;
- filesystem search, read or write;
- repository-history search;
- network or web access;
- environment lookup;
- memory read, protected-memory retrieval or memory write;
- LLM inference;
- embedding or vector-database access;
- semantic-similarity or nearest-neighbor selection;
- learned parser or neural classifier use;
- RAG;
- route registration;
- capability routing;
- tool activation;
- action execution;
- outward rendering;
- evidence validation;
- delivery authorization.

## 11. Later authority ownership

Slice 36H does not create concept or sense authority, predicate identity, participant roles, CandidateMeaning, gate disposition, clarification-required status, rejection, truth determination, evidence validity, permission, capability selection or execution authority.

These remain deferred to their separately governed slices and systems:

- Slice 37 — concepts and senses;
- Slice 38 — predicates and participant roles;
- Slice 39 — CandidateMeaning construction;
- Slice 40 — gate evaluation and ambiguity, clarification, rejection or blocked-progression disposition;
- MSM-v1 — semantic custody only after later meaning authority acts;
- MEA — unresolved problem-manifest evolution in its separate domain.

## 12. Mathematical direction

The integrated chain preserves the intended mathematical direction:

- `I_t` is the exact immutable input-event custody record;
- `Pi_s(I_t) = F_0` is deterministic reversible source-field projection;
- `G_r(F_0) -> {B_1, B_2, ..., B_n}` creates operator-binding candidates;
- `O_k(P_i) -> P_i_prime` creates an immutable successor candidate state;
- `D(P_1, P_2, ..., P_n)` yields bounded structure or explicit non-progress.

No step upgrades this result into governed meaning.

## 13. Rollback boundary

The runtime stores only immutable rollback metadata. It cannot execute Git or mutate the repository.

External verification must prove that a separate recovery clone can check out:

- pre-Slice-36 commit `6089037388680c144ff666cd3737a03e1ff34ef5`;
- pre-Slice-36 tree `a32d8159367a5d9ac23c6363d7c577fc3a684046`.

The live repository must remain unchanged during rollback proof.

## 14. Acceptance boundary

The runtime does not grant technical acceptance to itself. The final verifier, exact commit evidence and Decision Owner acceptance are required. Slice 36H does not authorize release, production readiness or push.
