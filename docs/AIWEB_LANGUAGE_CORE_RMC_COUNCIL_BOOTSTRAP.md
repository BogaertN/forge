# AI.WEB Language Core, RMC, and Operator Council bootstrap

Status date: 2026-07-29

This is an executable preview foundation, not a claim that the final operator
OS or a complete English language has been finished.

The generalized automatic operating path and its remaining capability roadmap
are documented in
[`FORGE_SYMBOLIC_OPERATOR_INTERPRETER_ROADMAP.md`](FORGE_SYMBOLIC_OPERATOR_INTERPRETER_ROADMAP.md).
The eight fixtures below remain bootstrap proofs; they are not the list of
questions Ask Forge is allowed to answer.

## Installed live path

Ask Forge now exposes this deterministic, response-only path:

```text
exact source custody
  -> character/source-form projection
  -> Forge-owned concept and sense proposals
  -> predicate and participant-role frames
  -> expectancy / congruity / connectedness / purport gates
  -> exact-identity RMC evidence
  -> unique meaning: candidate wording -> exact semantic Echo comparison
                    -> five-role Operator Council recommendation
                    -> immutable Recursive Manifest Compiler output record
                    -> closed symbolic-grammar language renderer
                    -> full-contract symbolic Echo decode and comparison
                    -> eligible definition: explicit one-time operator approval
                                           -> visible answer delivery
                    -> non-answer construction: controlled restatement preview
                                                -> no delivery
  -> ambiguity: preserve every admitted alternative
                -> governed clarification question preview (not delivered)
                -> next manually entered complete source is recompiled
                -> exact prior alternative match: immutable re-entry receipt
                -> no exact match: hold without Council, rendering, or delivery
```

The implementation does not create a model token stream, subword pieces,
numeric token IDs, embeddings, vectors, or similarity scores.  A source form
is an exact character span used to preserve and reconstruct the operator's
input; it is not an LLM token.

The Council is recommendation-only.  It cannot decide for Forge, execute a
tool, perform an action, write memory, or deliver wording.  The additional
Forge governance step happens before output compilation; within the referenced
Recursive Manifest Compiler substream, meaning still precedes the immutable
manifest, the manifest precedes human-language rendering, and rendering
precedes exact Echo validation.  The renderer expresses a selected meaning but
cannot invent or choose one.

This is not routed through the older GP-014/GP-015 verified-mathematics path or
the older generic approximate renderer.  Those paths remain unchanged.  The
Language Core renderer is deterministic and its Echo compares the complete
symbolic contract: speech act, purport, polarity, frame, grammar rule,
predicate, roles, concepts, senses, relations, declared request-to-response
transition, unique decode, and full source coverage.  A shared semantic
signature alone is not sufficient.

A genuinely ambiguous result remains `HELD` at the compiler boundary and
contains a nested `CLARIFICATION_REQUIRED` preview.  The preview is bound to
the exact compiler result and receipt, source custody, RMC evaluation, semantic
contracts, and every gate-admitted alternative.  Before projecting it, Forge
deterministically replays the complete compiler result and fails closed on any
custody, gate, candidate-authority, RMC, Echo, boundary, receipt, or result-ID
mismatch.  It does not select an option or authorize a tool, action, answer
delivery, or memory write.  The operator can enter a new complete exact-source
request that names the intended meaning.

That next manually entered request carries only the immediately prior
clarification request ID and exact original source.  Forge reconstructs and
validates the prior request, recompiles the new complete source against the
same immutable RMC snapshot, and accepts it only if exactly one gate-admitted
meaning matches exactly one preserved alternative.  It never consumes an
option label as meaning and never auto-submits an option.

Displaying this read-only evidence to the operator is an observable preview
exposure, so its telemetry says `operator_preview_exposed=true` and
`clarification_question_preview_exposed=true`.  It separately records
`live_clarification_session_started=false`,
`clarification_response_consumed=false`, and
`answer_delivery_performed=false`.  Thus “not delivered” means no governed
answer was delivered and no live clarification exchange was started; it does
not pretend the operator-visible preview was hidden.

This Forge-owned preview is not an activation or modification of the older
frozen Slice 12 ambiguity/clarification scaffold.  Slice 12 remains
scaffold-only with no runtime effect, no user-facing question emission, and no
expression-rendering authority.  The two schemas are intentionally separate.

## What the current registry actually contains

The Forge provisional seed contains 90 concepts, 90 senses, 89 predicate
definitions, and 7 participant roles.  Definitions are Forge-owned provisional
records.  Imported packets, Google Drive documents, Panini research, Chomsky
research, and the glyph reference list do not become canon by being present.

The pasted expansion transcript proposed 106 A-word keys, but its script left
the `concepts` list empty and ended after a quota error.  It therefore did not
install the claimed batch.  Nineteen of those names overlap the present
registry; 87 do not.  The old test demanding 1,000 A-words was not evidence of
semantic correctness and has been replaced by registry integrity, grounding,
determinism, exact-source, and authority-boundary checks.

A dictionary-wide A-to-Z import is not the next safe step.  One spelling can
have multiple senses and grammatical roles, while verbs need declared
inflections and participant frames.  Flat bulk entries would make the compiler
look larger while teaching it incorrect meanings.

## Governed semantic charter

Forge now has one immutable **proposed** semantic charter.  It does not declare
itself active or canonical.  It binds seven exact concept/sense pairs, six
predicates, six effective roles, nine construction contracts, and these eight
replay fixtures:

```text
What does language core mean?
What is RMC?
Please inspect the manifest.
Can Forge report status?
Forge uses RMC memory.
Forge does not use vector memory.
Forge is a system.
Compare RMC memory and vector memory.
```

Every fixture must replay to the same concept, sense, predicate, role,
construction, polarity, speech-act, purport, and semantic-signature identities.
For example, a positive RMC record cannot support a negated input, and a
statement record cannot support a modal question.  Exact spelling alone is not
enough.  In the charter's empty-memory replay, the ambiguous bare word `core`
remains held and broad generated A/B sentences remain outside the proposal.
The proposed charter has no runtime selection authority; separately promoted
exact semantic-contract RMC evidence may later resolve a bounded ambiguity,
and that influence must be reported as `context_used_for_selection`.

## Chomsky research alignment

Chomsky describes I-language as a finite generative system that can construct
an unbounded set of hierarchical expressions, and distinguishes the internal
conceptual-intentional structures from their later externalization.  Recent
work with Marcolli and Berwick gives Merge an algebraic formulation and extends
it toward an algebraic syntax-semantics interface:

- [Fundamental Operations of Language](https://cadernos.abralin.org/index.php/cadernos/article/view/271)
- [Mathematical Structure of Syntactic Merge](https://arxiv.org/abs/2305.18278)
- [Syntax-semantics interface: an algebraic model](https://arxiv.org/abs/2311.06189)

The engineering inference for Forge is to prioritize a small explicit
composition algebra, hierarchical structures, semantic interfaces, and
verification over a flat dictionary count.  Chomsky's work does not establish
Forge's RSOC glyph meanings or an RMC resonance-memory law; those remain
separate Forge hypotheses that require their own definitions and tests.

## RMC connection state

The Ask Forge adapter is connected to a trusted exact-ID RMC provider.  The
only admitted root is:

```text
memory/rmc_language_core_v1/stable
memory/rmc_language_core_v1/live
```

Records must be immutable and content-addressed, match the active Forge
registry, carry exact concept/sense/relation/role/ancestry identities, and
include source and operator-approval receipt identities.  Before runtime
admission, the loader also derives and verifies the one exact promotion receipt
for that record and stable target.  An approved record copied into `stable`
without its second-stage promotion evidence is rejected.  A malformed,
tampered, linked, unsafe, or unknown record rejects the whole snapshot.

The RMC Memory tab now provides a separate governed transaction:

```text
Status -> Prepare (no write)
       -> Approve (source + approval receipts only)
       -> Promote (one exact stable record + promotion receipt)
       -> Restart Forge to reload the trusted snapshot
```

Approval and promotion each require their exact token, an exact
content-addressed confirmation phrase, a short-lived one-time nonce, and a
strict local same-origin JSON POST.  Mutation routes reject query parameters,
duplicate JSON keys, cross-site requests, missing browser-origin evidence, and
oversized bodies.  Ask Forge has no call path to any of these mutations.

### Current trust boundary

The receipts are deterministic, content-addressed evidence; they are not a
cryptographic login or human signature.  The installed boundary trusts the
loopback Forge process and the same local OS user.  A future build needs an
authenticated operator key or OS credential if hostile software running as
that same user is in scope.  A crash or I/O fault between the receipt and
record links can also leave an orphan receipt; the provider rejects incomplete
chains, but recovery reporting for that rare partial-write case is still a
follow-up.

The current state is `TRUSTED_STRUCTURED`: all eight charter fixtures have
operator approval and promotion receipts and load as eight stable records,
with zero live records and zero rejected records.  This completes the bounded
bootstrap evidence set; it does not make the proposed charter automatically
canonical or turn it into a complete language.

With no matching RMC record, Language Core can still produce a candidate
meaning and Echo preview, but the Operator Council correctly returns
`HOLD_FOR_EVIDENCE`.

A fresh-process promoted-baseline verifier now proves all eight exact fixtures
receive complete semantic-contract RMC support and recommendation-only Council
output.  Five controlled polarity, speech-act, grammar, predicate, and concept
mismatches remain held.  The verifier also snapshots every promoted record and
governance receipt before and after the run and reports zero memory mutations.

## Recursive Manifest Compiler output state

The implementation follows the architecture in the inspected Google Drive
reference titled **Untitled document**, whose manuscript title is *The
Recursive Manifest Compiler: A Traceable Symbolic Architecture for Meaning
Compilation, Drift-Bounded Novelty, and Human-Readable Output*.  The Drive
document is design provenance, not runtime canon.

Each selected, exactly supported meaning now compiles into a content-addressed
output manifest binding source custody, the selected semantic contract, all
four meaning gates, exact-ID RMC evidence, compiler trace, compiler Echo, and
the recommendation-only Council result.  A closed renderer derives one
language candidate from that manifest.  Forge then reparses that exact output
and issues a second full-contract Echo receipt.  Rendering and Echo perform no
model call, token stream creation, embeddings, vectors, similarity scoring,
filesystem or memory write, tool route, action, or answer delivery.

The eight promoted fixtures now divide deliberately:

- `What does language core mean?` and `What is RMC?` produce definition-answer
  manifests.  After exact Echo passes, the operator may prepare and approve one
  delivery with an exact phrase and short-lived, one-time same-session nonce.
- The other six fixtures produce deterministic controlled restatements.  They
  remain preview-only because a restatement is not a status report, inspection
  result, comparison result, or executed action.  Each needs its own typed
  Forge result producer before answer delivery can be considered.

The delivery request never accepts browser-authored answer text.  On both
prepare and approve, Forge recomputes the whole preview and exact evidence
chain.  Approval returns only the already validated definition text and an
immutable delivery receipt.  It does not write RMC or any other memory.  The
current local same-origin receipt records operator confirmation but explicitly
does not claim cryptographic operator identity authentication.

This proves that Forge can render language output before the natural-language
system is complete.  The safe growth unit is a vertical construction slice:

```text
exact input forms -> symbolic composition -> exact RMC evidence
                  -> typed meaning/result -> output manifest
                  -> deterministic rendering -> exact Echo
                  -> explicit delivery policy
```

Unsupported forms remain held.  There is no need to finish an A-to-Z lexicon
first; add only the words, senses, inflections, roles, and output rules needed
by the next tested construction family.
